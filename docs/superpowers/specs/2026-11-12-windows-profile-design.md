# Windows 사용자 보호 기본 프로필 — 승인된 ②안

사용자는 ② Windows 사용자 DPAPI 저장형 개발을 승인했다. 기본 프로필 한 개를 저장해 다음 실행에서 WEC8500 ID·비밀번호만 입력하도록 한다. 원본 안정화 브랜치는 보존한다.

## 범위
일반 설정(IP/포트/AP ID/명령 문법/NAT/제한시간/옵션)과 선택한 AP 목록·이름을 복원한다. AP 비밀번호 및 변경 목표 공유키는 각각 명시적으로 선택했을 때만 Windows 사용자 범위 DPAPI로 저장한다. WEC8500 ID·비밀번호, 결과/원문/세션 상태는 저장하지 않는다. 조회 결과의 키를 목표 키로 자동 채우지 않는다. Windows API는 ctypes로 호출하며 외부 런타임 의존성을 추가하지 않는다.

## 저장과 보호
`%LOCALAPPDATA%/WEC8500_WIPS_Manager/settings/profile.json` 한 파일 안에 허용된 일반 설정과 암호문 블록을 구분한다. 전체 파일은 암호화 성공 뒤 같은 폴더 임시 파일에서 원자적 교체한다. 비밀은 평문 파일/로그/환경변수/명령 인자로 기록하지 않는다. DPAPI LOCAL_MACHINE을 사용하지 않는다. 암호문은 종류 및 컨트롤러/AP 계정/포트, 공유키는 목표 서버에도 연결한다. 복호화 실패/잘못된 파일/대상 불일치는 수동 입력을 안내하며 자동 접속하지 않는다. 오류 시 기존 파일을 보존한다. 삭제는 프로필만 지우며 보고서/백업의 안전 삭제를 보장하지 않는다.

## 화면과 사용
새 프로필 도구막대에서 저장/불러오기/삭제와 저장된 비밀번호 사용을 제어한다. 저장 대화상자에 AP 암호·공유키·AP 목록의 별도 선택과 확인을 제공한다. 시작 시 일반 값과 암호문만 읽고 비밀 입력창을 채우지 않는다. 필요한 작업의 실행 입력 생성 시에만 복호화한다. 조회에서는 목표 공유키를 복호화하지 않는다. WEC8500 자격증명은 시작/불러오기 시 공란이다. 저장된 실장비 프로필 로드시 실장비 모드를 표시하지만 연결/변경은 실행 버튼과 기존 확인을 반드시 거친다. 모의 데이터로 실장비 프로필을 덮어쓸 수 없다. 작업/저장 중에는 프로필 변경을 막는다. 같은 창의 이어하기는 기존 메모리 스냅샷을 사용한다.

## 구현 경계
새 `ProfileApp`이 기존 WipsApp을 상속하여 도구막대와 설정 입력 생성만 확장한다. 기존 GUI/Runner/전송/보고서 코드는 유지하고 app.py 진입점만 바꾼다. 프로필 없음 또는 미지원 OS에서는 기존 수동 입력으로 동작한다. 다중 프로필/자동 접속/재시작 이어하기/비밀번호 내보내기는 범위 밖이다.

## 보호 한계 및 검증
같은 Windows 사용자 권한의 악성코드, Telnet 평문 전송, 기존 공유키 원문 보고서는 별도 위험이다. 사내 정책 허용을 전제로 한다. Linux에서는 주입한 보호기와 Win32 API 계약을 검사하고 실제 Windows DPAPI 테스트는 별도 제공해 미수행임을 밝힌다. 기존 전체 회귀 및 GUI/원자적 실패/손상/목표변경/암호 미유출/모의 분리 테스트를 수행한다.
