# WEC8500 WIPS Manager design

User requested a Python program for Windows 11. All IPs, IDs, passwords and WIPS shared keys are entered locally at runtime. Route: PC Telnet -> WEC8500 interactive CLI -> nested AP SSH. No connection to real equipment is performed during development.

Use Tkinter and standard-library socket/select Telnet adapter (no third-party dependencies and no removed telnetlib). Keep one controller Telnet session across the batch; sequentially enter each AP then send exit and verify the exact original controller prompt before entering the next AP. Default AP ID root, port 50022. The user explicitly requested automatic yes for first-time AP host-key questions; enable by default, optionally offer manual fingerprint confirmation, and still reject changed keys. Input is IPv4 list/paste or CSV. Actions are inspect and apply. Apply rereads the current summary, changes only the selected WIPS server/key (and NAT only if explicitly selected), then reads again and compares exact fields. Result wording is configuration verification, never server connectivity verification. No reboot, mode change, save, automatic mutation retry, or rollback.

Support documented `config wips server IP NAT KEY` and the user-provided unverified `config wips server IP KEY` as explicitly selected syntax, no silent fallback. Default NAT policy is preserve. Ports are configurable, controller Telnet 23 / AP sensor SSH 50022. Unknown prompts or unparseable summaries stop that AP without modifying it. Passwords/keys are neither persisted nor logged; exports contain allowlisted fields only. Controller Telnet login sends ID then password once after recognized prompts; no controller SSH host-key mechanism. New AP SSH questions auto-yes by default per user request; changed keys fail. Default stop on first failure. Stop cancels subsequent work; after a command may have been sent, report unknown rather than failure/success if verification cannot complete.

Alternatives: direct PC->AP needs reachability not requested; SSH forwarding is not documented on the controller. Use the requested controller's CLI SSH client. Ship a Python source ZIP with requirements, launch/install .cmd files, Korean instructions, offline install instructions, tests and an explicitly labelled network-free demo.

Public interfaces: RunConfig (connection fields, ap_ips, server_ip/shared_key, syntax=with_nat|without_nat, nat_mode=keep|1|2, timeout=20, demo=False, stop_on_error=True); Runner(config, emit, confirm, stop, session_factory=None).run(mode=inspect|apply) -> list[Result]. emit(kind, data) with kind log/progress/result/done. confirm(title,message)->bool. Session(config, stop, confirm).connect(ap_ip), execute(command)->str, leave_ap(), controller_ready property, close(). Result adds controller_return. RunConfig adds auto_accept_ap_host_key=True. Exit failure aborts even when stop_on_error=False; verified settings remain visible but status indicates return failure.

## v1.3 read-only target IP verification

The verify_ip action requires a target WIPS server IP but no shared key. It reads show config wips summary once per AP and exits without configuration commands. Match and mismatch are separate results; mismatch continues the AP list. Invalid reads follow the existing error policy, while cancellation and failed controller return halt the batch. Current and target IPs are included in the UI and CSV. This verifies the current configured IP only, not WIPS connectivity or historical change.
