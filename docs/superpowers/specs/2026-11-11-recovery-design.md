# v1.4 회사 내부 사용을 위한 자동 복구

사용자는 실제 장비 데이터를 외부로 제공할 수 없다. 현장 원인 확정이나 데이터 제출을 전제로 하지 않고, 재현된 프로그램 문제를 수정하고 사내 PC 자체에서 상황을 확인하도록 한다.

## 결정
- 기존 Python/Tk/Windows EXE 유지. 자동 복구 기본 활성화, 일시적 통신 실패에 한해 AP당 추가 2회(3초/10초 후).
- 같은 AP에 새 Telnet → SSH로 재접속하여 항상 설정부터 조회한다. 기존 불확실한 세션은 재사용하지 않는다.
- 변경 전송 이후 실패하면 원래 NAT 목표를 유지하고 현재 IP·키·NAT가 모두 읽힐 때만 적용 여부를 판단한다. 이미 목표와 같으면 재전송하지 않는다. 키가 마스킹되거나 필요한 값이 없으면 확인 필요로 남긴다.
- 인증·호스트키·문법·해석 오류와 사용자 중지는 자동 재시도하지 않는다. 제한 초과 이후에는 기존 오류 중단 정책을 적용한다. 컨트롤러 상태가 불명확하면 후속 AP로 보내지 않는다.
- 명령 사이의 CR/LF/탭/공백만 추가 수신된 경우 허용한다. 비어 있지 않은 비동기 로그나 임의 프롬프트는 추측하지 않는다.
- GUI 갱신 예외 시 중지 요청과 정적 오류 표시 후 이벤트 확인을 계속하여 작업 종료 상태를 반영한다.
- 현재 단계·경과시간·최근 응답·재시도 대기를 표시한다.
- 같은 앱 세션에서는 미완료 이어하기 버튼이 마지막 실행 목표·접속정보의 메모리 사본을 사용한다. 성공 AP는 보존하고 불확실한 AP는 먼저 재조회한다. 암호를 디스크에 저장하거나 앱 재시작 뒤 자동 연결하지 않는다.
- PC 내부 records 폴더에 제한된 진단 항목과 결과 CSV를 자동 저장한다. 장비 원문·명령 원문·ID·암호·공유키는 기록하지 않는다. 업로드·원격지원 기능 없음.
- 현장 장애 원인과 실제 Windows/실장비 호환성은 이 개발 환경의 테스트만으로 확정하지 않는다.

## 선택 근거
단순히 오류 중단을 해제하는 방법은 세션 단절을 복구하지 못한다. 마지막 config를 바로 반복하는 방법은 이미 적용됐을 때 중복 변경한다. AP 단위 재접속과 선조회는 이 두 문제를 피하면서 기존 목표와 검증 기준을 유지한다.
