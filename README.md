# WEC8500 WIPS Manager 1.5.1

> 안정화 빌드 `stabilization.1`: 기능·화면·명령·정책은 유지합니다. 수정 및 검증 범위는 [STABILIZATION.md](STABILIZATION.md)를 참고하세요. Windows 및 실장비 검증은 사용자 확인 대상입니다.

Windows 11에서 사용하는 Python GUI입니다. **PC → WEC8500 Telnet → AP별 SSH** 순서로 접속하여 WIPS 서버 주소와 공유키를 변경하고, 다시 조회한 설정값을 비교합니다.

IP, ID, 비밀번호, 특정키는 실행 화면에 입력합니다. 로그인 ID·비밀번호는 결과 파일에 저장하지 않습니다. 장비에서 조회한 WIPS 공유키는 사용자 저장 HTML·CSV·TXT에 원문으로 포함되며, 자동 진단 기록에서는 마스킹합니다. 입력한 접속정보와 목표 키는 장비 접속·설정에만 사용합니다. 원본 터미널 출력은 로그로 저장하지 않습니다.

## 빠른 시작

EXE 배포본은 ZIP을 압축 해제하고 `WEC8500_WIPS_Manager_v1.5.1_stabilization.1_Win11_x64.exe`를 실행합니다. Python 런타임이 포함되어 있습니다. 아래 설치 절차는 Python 소스 배포본용입니다.


1. ZIP 전체를 압축 해제합니다. 압축파일 안에서 바로 실행하지 마세요.
2. Windows에 Python **3.11 이상**을 설치합니다. python.org 설치 프로그램에서 **Python Launcher와 Tcl/Tk**를 포함하세요. 관리자 권한은 필수가 아닙니다.
3. `start.cmd`를 실행합니다. 별도 pip 패키지는 필요하지 않습니다.
4. 필요하면 `install.cmd`로 프로젝트용 가상환경을 만들 수 있습니다. 인터넷 없이 동작합니다.
5. **모의 데이터 채우기 → 사전 조회 → 변경 및 검증**으로 화면을 확인합니다. 기본값은 모의 실행이며 네트워크 접속을 하지 않습니다.

직접 실행하려면 프로젝트 폴더에서:

```powershell
py -3 app.py
```

모의 실행은 `py -3 app.py --demo`로 시작합니다. Python과 Tkinter만 필요하며, 실제 실행도 추가 패키지가 필요하지 않습니다.

## 실제 장비에서 사용

1. **모의 실행 체크를 해제**합니다.
2. WEC8500 IP, **Telnet 포트(기본 23)**, 컨트롤러 ID/PW를 입력합니다. 컨트롤러 로그인 질문에 맞춰 ID와 비밀번호를 각각 한 번 입력합니다.
3. AP 계정 기본값은 `root`, SSH 포트 기본값은 `50022`입니다. AP 비밀번호를 입력합니다. 계정·포트는 필요 시 수정 가능합니다.
4. `AP 최초 접속 확인에 yes 자동 응답`은 기본 활성화입니다. 신규 AP의 SSH 최초 연결 yes/no 질문이 나올 때만 yes를 보내고, 비밀번호 요청을 받은 다음 지정한 AP 비밀번호를 입력합니다.
5. AP IP를 한 줄에 하나씩 붙여넣거나 `ap_ips_example.csv`처럼 `ap_ip` 열을 가진 CSV를 불러옵니다. 중복 IP는 제거됩니다. 선택적으로 hostname 열을 함께 넣을 수 있습니다. ID·비밀번호 등 다른 열은 사용하지 않습니다.
6. 먼저 AP 한 대만 넣고 **사전 조회**를 실행합니다. 이 작업은 변경 명령을 보내지 않습니다.
7. 새 WIPS 서버 IP와 특정키를 입력하고 해당 펌웨어의 명령 문법을 선택합니다.
8. **변경 및 검증**을 누르면 대상 AP 수·서버 주소·문법·NAT가 표시됩니다. 내용을 확인한 뒤 실행합니다.
9. 결과를 확인하고 **결과 CSV 저장**을 누릅니다. 이후 필요한 AP 목록을 넣어 반복합니다.

장비는 사용자의 PC에서 접속합니다. 이 프로그램은 인터넷 서비스가 필요하지 않으며 서버 IP를 외부 API로 전송하지 않습니다. 진단 기록도 사용 중인 PC 안에만 저장합니다. Python 설치가 되어 있으면 추가 패키지 다운로드 없이 사용할 수 있습니다.

## 변경 없이 목표 서버 IP만 확인

1. **모의 실행 체크를 해제**하고 컨트롤러·AP의 접속 정보와 AP IP 목록을 입력합니다.
2. **WIPS 서버 IP**에 확인하려는 목표 서버 주소를 입력합니다.
3. **③ 서버 IP 일치 확인**을 누릅니다. 이 기능에는 WIPS 공유키를 입력할 필요가 없습니다. 장비 로그인 비밀번호는 필요합니다.
4. 각 AP에서 `show config wips summary`로 읽은 현재 서버 IP를 목표 IP와 비교합니다. `config` 명령은 보내지 않습니다.
5. **IP일치 / IP불일치**, 목표 서버, 확인된 서버를 보고 결과 CSV를 저장합니다. 상세창에는 IP 확인 결과와 컨트롤러 복귀 여부가 표시됩니다.

IP가 다른 AP를 발견해도 나머지 AP를 계속 조회합니다. 자동 복구가 켜져 있으면 일시적인 통신 오류는 같은 AP에 재접속하여 다시 조회합니다. 복구 한도 초과나 재시도 불가 오류에는 오류 중단 옵션이 적용되며, 컨트롤러 상태를 확인할 수 없으면 후속 AP를 중단합니다. NAT·공유키는 이 기능의 판정 대상이 아니며 서버 연결·인증 상태를 검사하는 기능도 아닙니다.

**일치 결과는 조회 시점의 현재 설정 확인입니다.** 이 기능만으로 과거 변경 작업의 실행 여부나 재부팅 후 유지 여부를 판단하지 않습니다. `[모의]` 표시는 실제 장비 결과가 아닙니다.

## v1.5 AP별 HTML·CSV·TXT 보고서

장비 작업이 끝나면 **HTML·CSV 보고서 저장**을 눌러 저장할 상위 폴더를 선택합니다. 날짜·시간이 포함된 새 폴더에 `report.html`과 `results.csv`가 함께 생성됩니다. 저장 중에도 화면은 응답하며, 저장이 끝나면 **보고서 열기**로 PC의 기본 브라우저에서 열 수 있습니다. Python·웹서버·인터넷은 HTML 열기에 필요하지 않습니다.

- HTML: AP IP·hostname·목표/조회 서버 IP·판정·조회 시각, 전체/일치/불일치/실패/미실행/판정 없음 개수, 검색·정렬·필터·페이지 나눔(50/100/250개).
- AP 행의 상세 버튼: 이름 출처, WIPS 모드·NAT, 최초/변경 후 조회 항목, 오류 단계·코드·재접속 횟수.
- Excel용 CSV: 전체 AP가 한 행씩 들어가며, UTF-8 BOM 형식입니다. 조회 항목에 줄바꿈이 있어도 따옴표로 묶여 한 CSV 레코드로 저장됩니다.
- 선택 TXT: 프로그램의 결과 표에서 Ctrl/Shift로 AP를 선택하고 **선택 AP TXT 저장**을 누릅니다. 별도 날짜 폴더의 `details/AP_IP.txt`에 선택한 AP만 저장됩니다.
- HTML 안에서도 현재 필터 결과 CSV, 선택 AP를 모은 TXT, 상세창의 개별 AP TXT를 내려받을 수 있습니다. HTML에서의 파일 저장은 브라우저 다운로드 폴더를 사용합니다.
- TXT와 상세 화면은 **조회 항목 정리본**입니다. 응답 전체를 복사하지 않고 인식한 서버 IP·NAT·WIPS 모드·공유키를 정리합니다. v1.5.1부터 `wips sharedkey`는 장비가 반환한 값을 그대로 표시합니다.
- `observed_at`은 마지막 유효한 조회 시각, `time`은 AP 작업 시작 시각입니다. 조회한 시점 이후 설정이 달라질 수 있습니다.
- IP 일치와 전체 검증 결과는 별도입니다. IP가 같아도 키·NAT가 확인되지 않으면 부분확인/추가 확인 표시를 유지합니다.

모든 보고서는 PC 안에서 생성되며 외부 글꼴·CDN·분석 서버·업로드 기능을 사용하지 않습니다. 보고서에는 IP·hostname·조회된 WIPS 공유키가 포함되므로 사내에서 보관하세요. `report.html` 하나만 복사해도 검색과 상세 조회가 동작합니다. 함께 제공한 예시 HTML은 모의 데이터입니다.

## v1.5.1 WIPS 공유키 원문 표시

`show config wips summary` 응답의 `wips sharedkey` 값을 프로그램에서 마스킹하지 않습니다. AP 결과 행을 더블클릭한 상세창, HTML 상세, 저장한 CSV의 `summary_before`·`summary_after`, AP TXT에 장비가 반환한 값이 표시됩니다. 변경 작업은 변경 전·후 조회 값을 각각 보존합니다.

장비가 `******`, `<hidden>`, `[MASKED]` 등으로 반환하면 그 표시를 그대로 남깁니다. 입력한 목표 키로 조회값을 채우거나 숨겨진 값을 복원하지 않습니다. 이미 v1.5에서 저장한 마스킹 보고서는 복원되지 않으므로 v1.5.1에서 다시 조회해 저장하세요. 중복·제어문자·과도하게 긴 키 항목은 유효한 단일 값으로 표시하지 않습니다.

자동 생성되는 **기록 폴더**의 진단 파일은 계속 공유키를 마스킹합니다. 원문 키를 확인하려면 화면의 상세창 또는 **HTML·CSV 보고서 저장 / 결과 CSV 저장 / 선택 AP TXT 저장**으로 만든 결과를 사용하세요. 장비 로그인 ID·비밀번호와 알 수 없는 응답 항목은 보고서에 넣지 않습니다.

## hostname 수집과 CSV 목록

**컨트롤러 AP 이름 조회**는 화면 기본값이 켜짐입니다. 인증된 컨트롤러에서 `show ap summary`를 조회하고, AP_NAME과 IPv4Addr를 대응시켜 이름을 수집합니다. AP별 WIPS 조회 명령은 기존 `show config wips summary`를 사용합니다.

이름 우선순위는 **컨트롤러 AP_NAME → CSV에 입력한 hostname → AP 프롬프트**입니다. 출처를 문서에 함께 표시합니다. 컨트롤러의 AP 이름이나 프롬프트 표시명은 OS의 시스템 hostname과 다를 수 있습니다. 일반적인 `AP#`, `root`, `localhost`는 고유한 이름으로 간주하지 않으며 확인되지 않으면 **미확인**으로 표시합니다. AP가 접속되지 않아도 CSV에 이름이 있으면 결과에 남습니다.

선택적 이름 조회가 지원되지 않으면 이름 없이 WIPS 작업을 진행합니다. 이름 조회가 타임아웃·연결 종료로 끝나면 불확실한 연결을 닫고 한 번 새로 로그인한 뒤 이름 조회를 반복하지 않고 AP 작업을 진행합니다. 인증 실패 등은 임의로 우회하지 않습니다. 이름 조회 때문에 지연되는 환경은 해당 옵션을 끄고 CSV 이름을 사용할 수 있습니다.

CSV 예시(동봉된 `ap_ips_example.csv` 사용 가능):

```csv
ap_ip,hostname
192.0.2.11,LAB-3F-AP01
192.0.2.12,LAB-3F-AP02
```

IP 열은 `ap_ip`, `IP`, `AP IP`를 지원합니다. 이름 열은 `hostname`, `ap_hostname`, `AP Name`, `호스트명` 중 하나를 선택합니다. 일반 `name` 열이나 계정·암호 열은 이름으로 읽지 않습니다. 중복 IP에 서로 다른 이름이 있으면 입력 오류로 알려줍니다. 이름을 수정한 뒤 새 목표로 실행하려면 새 작업 버튼을 사용하세요. 이어하기는 이전 실행 목표와 이름 목록을 사용합니다.

제조사 작성 문서 참고: [Samsung WEC8500/8050 Maintenance Manual v5.1](https://www.ntsdirectclients.com/Documentation/Customersonly/SamsungWLANDOCS/WLAN%20Product%20Documents/wec8500wec8050_apc_maintenance%20manual_ver5%201_april2015.pdf), `show ap summary`의 AP_NAME / IPv4Addr 항목. 해당 펌웨어 실장비 검증을 대신하지 않습니다.

## 자동 복구와 미완료 이어하기

- **자동 복구(최대 2회)**는 기본 활성화입니다. 통신 타임아웃·연결 끊김이면 현재 연결을 닫고 3초, 10초 간격으로 새 Telnet → 동일 AP SSH 연결을 시도합니다. 최초 시도 포함 최대 3회입니다.
- 복구 시 무조건 `show config wips summary`부터 실행합니다. 변경이 이미 적용됐으면 다시 쓰지 않습니다. 변경 모드는 IP·키·최초 NAT 목표를 모두 비교합니다.
- 변경 후 연결이 끊겼고 재조회에서 키가 가려지거나 NAT 목표를 확인할 수 없으면 **부분확인**으로 남깁니다. 확인할 수 없는 값을 추측해서 재전송하지 않습니다.
- 인증 실패·호스트 키 문제·잘못된 명령/조회 형식은 자동 반복하지 않습니다. 사용자가 중지를 누르면 대기 중인 재접속도 취소됩니다.
- 같은 프로그램 창에서 **미완료 이어하기**를 누르면 마지막 실행의 접속정보와 목표 설정으로 미완료 AP만 다시 조회·처리합니다. 이미 완료한 AP는 유지합니다. **화면에서 나중에 수정한 입력값은 이어하기에 사용하지 않습니다.** 목표를 바꾸려면 새 작업을 시작하세요.
- 이어하기 정보와 암호는 프로그램 메모리에만 있습니다. 프로그램을 닫았다가 다시 여는 경우 자동 복구되지 않으며, 접속정보와 미완료 AP 목록을 다시 입력해야 합니다.
- 화면에 현재 단계·단계 경과시간·최근 응답 이후 시간·재접속 대기를 표시합니다. 미실행도 전체 결과에 포함되며 종료 시 완료/확인필요/미실행 수를 구분합니다.

## PC 내부 진단 기록

**기록 폴더 열기** 버튼으로 해당 작업의 파일을 볼 수 있습니다. 기본 위치는 `%LOCALAPPDATA%\WEC8500_WIPS_Manager\records`입니다. 폴더 안의 작업별 하위 폴더에 다음 파일이 생깁니다.

| 파일 | 용도 |
|---|---|
| `job.json` | 작업 모드·목표 IP·포트·복구 옵션 |
| `state.json` | 마지막 작업 단계·시도·오류 코드 |
| `events.jsonl` | 시간순 단계·재시도·수신 활동·결과 |
| `results.csv` | 자동 기록된 AP별 결과. Excel에서 확인 가능 |

IP 주소 등 내부 운영정보는 포함됩니다. **ID·비밀번호·공유키·장비 응답 원문·전체 명령은 기록하지 않습니다.** 자동 전송이나 업로드 기능은 없습니다. 회사 내부에서 확인하고 보관 규정에 따라 삭제하세요. 로컬 기록 저장에 실패하면 화면에 표시하고 메모리에서 작업을 계속합니다. 이 경우 종료 전 결과 CSV를 직접 저장할 수 있습니다.

| 오류 코드 | 내부에서 확인할 사항 |
|---|---|
| `CONTROLLER_CONNECT_TIMEOUT` / `CONTROLLER_CONNECT_FAILED` | PC → WEC8500 Telnet 접속 경로·포트 |
| `CONTROLLER_LOGIN_TIMEOUT` / `AP_LOGIN_TIMEOUT` | 로그인 질문·응답 시간·프롬프트 형식 |

| `RETURN_TIMEOUT` | exit 후 원래 컨트롤러 프롬프트를 확인하지 못함 |
| `CONNECTION_CLOSED` / `IO_ERROR` / `AP_CONNECT_FAILED` | 연결 종료 또는 통신 오류 |

| `VERIFICATION_PARTIAL` / `VERIFICATION_MISMATCH` | 설정 일부 확인 불가 / 목표와 값이 다름 |

오류 코드는 실패 구간을 좁히기 위한 정보이며 회선·펌웨어 등의 근본 원인을 자동 확정하는 것은 아닙니다. 실제 장비 데이터를 외부에 제공하지 않아도 사내에서 확인할 수 있습니다.

## 명령 문법과 포트

삼성 WES 설치 매뉴얼(2015년 3월, 인쇄 31~34쪽)에서 확인한 형식:

```text
config wips server <서버IP> <NAT모드> <공유키>
show config wips summary
```

- **NAT 포함**: 위 문서 형식입니다. 기본값입니다.
- **NAT 생략**: 사용자가 제시한 `config wips server <서버IP> <공유키>` 형식입니다. 공개 문서로 검증되지 않았으며 해당 장비에서 지원하는 경우에만 선택합니다.
- NAT 기본 동작은 **기존 값 유지**입니다. 문서 기준 `1`은 미사용, `2`는 사용입니다. 읽은 값이 불명확하면 기본 문법에서는 변경하지 않습니다.
- 문법을 자동 추측하거나 오류 후 다른 문법으로 변경 명령을 다시 보내지 않습니다. 사전 조회는 현재 설정 조회이며 **변경 문법 지원 여부를 자동 판별하는 기능은 아닙니다**.
- 컨트롤러 **Telnet** 기본 포트는 `23`, AP 기본 포트는 문서의 **센서 SSH 포트 `50022`**입니다. 일반 AP 관리 SSH나 실제 설정에 따라 달라질 수 있으므로 수정할 수 있습니다.
- WEC8500 내부에서는 `ssh <AP_IP> <AP_ID> <AP_PORT>`를 사용합니다.
- 서버 변경 후 `save` 필요 여부는 자료에서 확인하지 못했습니다. 이 버전은 별도 저장·재부팅·모드 변경 명령을 실행하지 않으며, 재부팅 후 유지 여부를 검증하지 않습니다.

키에는 공백·줄바꿈·쉘 제어문자를 허용하지 않습니다. 지원 문자: 영문, 숫자, `! @ # % ^ * + = _ . , : / - [ ]` (1~256자). 지원하지 않는 문자가 포함되면 실행 전에 입력 오류로 표시합니다. ID는 영문·숫자와 `_ . @ -`를 지원하며 첫 글자는 영문·숫자·밑줄을 사용합니다.

## 결과 읽는 방법

| 결과 | 뜻 |
|---|---|
| 조회완료 | 현재 서버 IP/NAT를 읽음. 변경 없음 |
| IP일치 | 조회한 현재 서버 IP가 입력한 목표 IP와 같음. 설정 변경 없음 |
| IP불일치 | 조회한 현재 서버 IP가 목표 IP와 다름. 설정 변경 없음 |
| 변경확인 | 변경 후 서버 IP·키·NAT가 목표와 일치 |
| 이미일치 | 변경 전부터 모두 일치하여 변경 명령 생략 |
| 부분확인 | 서버 IP는 일치하나 키가 마스킹되었거나 NAT를 완전히 확인하지 못함 |
| 검증불일치 | 변경 후 조회한 값 중 목표와 다른 값이 있음 |
| 확인불가 | 변경 명령이 전달되었을 수 있으나 응답·검증을 완료하지 못함. 재조회 필요 |
| 실패 | 접속·사전 조회 오류 또는 명시적인 명령 오류 응답. 메시지 확인 |
| 복귀실패 | 조회·검증 이후 exit로 컨트롤러 복귀를 끝내 확인하지 못함. 검증한 값은 남기고 후속 AP는 중단 |
| 중지 | 변경 명령 전 중지 요청 처리 |
| 미실행 | 중지나 앞선 오류로 대상 AP 작업을 시작하지 않음 |

CSV의 `target_ip`는 확인할 목표 주소, `ip_check`는 서버 IP 비교 결과입니다.

표·CSV의 `controller_return`은 `복귀확인` / `미확인` / `미접속`으로 표시합니다. 변경된 서버 IP·키 검증과 컨트롤러 복귀 여부를 함께 확인하세요.

**변경확인은 설정값 비교 결과이며 WIPS 서버 연결·인증 정상 판정이 아닙니다.** 모의 결과는 화면과 CSV의 `simulated` 항목에 별도 표시됩니다.

**WEC8500 Telnet 연결 하나를 유지**하고 AP별로 `ssh → yes(질문이 있을 때만) → AP 비밀번호 → 사전 조회 → 서버 변경 → 결과 조회 → exit`를 반복합니다. `exit` 후 처음 확인한 WEC8500 프롬프트로 돌아온 것을 확인한 뒤에만 다음 AP에 접속합니다. 작업 종료 시 컨트롤러 연결도 닫습니다.

기본적으로 오류·부분확인·확인불가 발생 시 이후 AP를 실행하지 않습니다. `첫 오류 발생 시 중단`을 해제한 경우에도 **컨트롤러 복귀가 확인된 경우에만** 다음 AP를 처리합니다. 세션 단절이나 복귀 실패는 이 옵션과 관계없이 전체 작업을 중단합니다. 자동 복구가 켜져 있으면 일시적 통신 오류에 한해 새 컨트롤러 연결을 만들어 같은 AP부터 재조회합니다. 이미 변경한 AP는 자동 원복하지 않습니다.

`중지`는 이미 전달된 명령을 취소하지 않습니다. 연결·인증 단계에서는 설정한 대기시간 이후에 종료될 수 있으며 단계별 제한시간이 누적될 수 있습니다. 창을 닫아도 작업 세션의 종료를 기다립니다.

## 접속 방식·AP SSH 호스트 키·로그

- 컨트롤러는 Telnet으로 접속하므로 SSH 호스트 키 확인창이 없습니다. `login:` / `Username:` / `User Name:` / `ID:`와 비밀번호 질문을 처리합니다.
- **AP의 신규 SSH yes/no 질문은 기본적으로 자동 yes** 처리합니다. 자동 응답 체크를 해제하면 지문 확인창으로 전환됩니다. 이미 알려진 AP라서 질문이 없으면 yes를 보내지 않습니다.
- 프로그램은 컨트롤러 호스트 키 파일을 만들지 않습니다. 이전 버전에서 생성한 파일도 이번 버전에서는 사용하지 않습니다.
- AP 호스트 키 확인은 컨트롤러의 SSH 클라이언트가 처리합니다. **기존 키가 변경되었다는 경고는 자동 수락하지 않고 중단**합니다. 비밀번호 요청을 기다리며 비밀번호를 자동 반복 입력하지 않습니다.
- AP SSH는 WEC8500의 내장 클라이언트가 수행합니다. AP와의 SSH 호환성은 컨트롤러가 지원하는 알고리즘에 따릅니다. 프로그램은 관련 장비 설정을 변경하지 않습니다.
- PC↔컨트롤러 구간은 Telnet이므로 암호화되지 않습니다. AP 비밀번호와 설정 명령도 이 구간을 통과하므로 사내 관리망에서 사용하세요.
- AP/컨트롤러 프롬프트는 일반적인 `장비명#` 또는 `장비명>` 형식을 지원합니다. 두 프롬프트가 같거나 특수한 로그인 메뉴·프롬프트를 사용하는 장비는 작업을 중단할 수 있습니다.
- 장비 응답 전체를 저장하지 않고 명명된 조회 항목만 정리합니다. 사용자가 저장하는 보고서와 AP 상세에는 조회된 WIPS 공유키 원문이 포함됩니다. 자동 진단 파일에는 키 값을 마스킹합니다.
- 접속정보와 목표 키 입력값은 앱 종료 후 재입력합니다. 장비 조회로 확인한 공유키는 사용자가 저장한 보고서에 남습니다. Python 메모리의 암호학적 완전 삭제를 보장하는 제품은 아닙니다.

## 사내 오프라인 사용

Python 3.11 이상과 Tkinter가 설치되어 있으면 ZIP을 압축 해제하고 `start.cmd`만 실행하면 됩니다. pip 설치, Paramiko, wheelhouse, Windows Telnet 클라이언트 기능을 별도로 설치할 필요가 없습니다.

Python 3.13에서 제거된 `telnetlib`도 사용하지 않습니다. 표준 라이브러리의 socket/select를 이용한 Telnet 처리를 포함했습니다. `install.cmd`는 선택 사항이며 인터넷 없이 가상환경과 Tkinter 설치 상태만 점검합니다.

